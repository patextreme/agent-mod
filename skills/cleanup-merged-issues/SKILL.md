# Clean Up Merged Issue Work

Run only on explicit human invocation. Inspect all local branches matching `^issue-[0-9]+$`, including branches without worktrees. Preview candidates and obtain explicit confirmation before removing anything or pruning refs. Remote branch deletion is outside this skill's scope.

## Inspect

1. Read project instructions and delivery policy. Resolve the git common directory, repository identity, and the exact remote corresponding to that GitHub repository; do not assume `origin` points there. Check `gh auth status` and fetch that remote without pruning. Missing access or ambiguous repository/remote identity blocks cleanup.
2. Enumerate local issue refs with their tip SHAs and `git worktree list --porcelain` records. Preserve paths containing spaces. Record associated worktree paths, accessibility, lock/prunable state, branch upstream configuration, and remote tip when present. Identify the main worktree and any worktree containing the current session's working directory. Skip those worktrees, missing/prunable records, inaccessible or locked worktrees, and unexplained branch/path associations; preserve their branches.
   - For each candidate worktree, collect `git -C <absolute-path> status --porcelain --ignored` as informational content only. Record the reported ignored paths (`!!` entries, respecting Git's path quoting) for the preview. Untracked/ignored content, tracked modifications, and initialized submodules are not skill-side eligibility gates; Git decides whether normal removal can proceed.
   - Separately establish and record the effective `status.showUntrackedFiles` applicable to Git's internal status subprocess in that target's actual removal context. Account for system/global/repository/worktree scopes, includes/conditional includes (including target gitdir and branch conditions), inherited environment-based configuration, and duplicate-value precedence. Record the effective value and the provenance/context establishing its applicability; do not infer it from the retained worktree, one config file, or one safe entry among duplicates.
   - Establish equivalence with the internal status context, not merely a successful `git config` query: inherited `GIT_CONFIG` can redirect `git config` to a decoy file without redirecting `git status`. Account for the actual Git executable, target gitdir/worktree, and inherited configuration environment used by removal. If that equivalence or the effective value cannot be established, pause the affected removal for operator reconciliation and preserve its branch.
   - Accept only unset (Git's default `normal`), `normal`, or `all`. Effective `no`, an invalid value, or an unknown result pauses the affected removal and preserves its branch. This configuration prerequisite is distinct from the informational content listing. Do not mutate configuration or inject invocation flags/environment overrides to satisfy it.
3. Query all matching PRs, including closed ones, with pagination and explicit repository selection. Match head repository and branch, and enforce the project's expected base branch. Record PR URL/number, state, merged time, and authoritative PR head SHA. A closing reference or branch name alone is not merge evidence. Retrieve missing head evidence from the PR API/commit records; if it cannot be established, skip the branch.
4. Mark a branch eligible only when exactly one matching PR is merged, no competing open or ambiguous PR exists, and the local tip equals that PR's recorded head SHA. If the remote branch still exists, require its tip to equal the same SHA. This exact match establishes the tip was pushed and reviewed even when squash/rebase merging breaks ancestry. Skip unexplained divergent, unpushed, or post-merge commits; do not infer safety from patch similarity or issue closure.

Branches without worktrees can qualify using the same PR/ref evidence. For branches with multiple associated worktrees, every association must be explained, pass the exclusion checks, and satisfy the configuration prerequisites before proposing that branch's cleanup.

## Preview and confirm

Show a table containing branch, local SHA, worktree path (or none), merged PR URL/time, and eligibility or exact skip/pause reason. For each candidate worktree, add:

- `Ignored files present: N reported paths — deleted by removal`, followed by the ignored-path listing (or explicitly none). This is informational, never a content gate or a guarantee of complete visibility or safe deletion.
- The effective status-configuration result and its applicability evidence, including unset/default `normal` where established, or the exact unsafe/unknown configuration blocker.

State the verified remote whose stale tracking refs will be pruned before removals. Propose only eligible branches; offer explicit selection or cancellation and recommend cleaning the verified candidates while retaining all skipped/paused work.

Disclose at preview/confirmation that Git checks content and then deletes recursively in separate, non-atomic operations. Under safe effective configuration, its refusal protects only non-ignored untracked/modified content observed in that check. Ignored content may be deleted; a writer changing content after the check can cause content loss. Neither the ignored-path preview nor this workflow makes removal race-proof.

Require the operator to explicitly confirm that all writers to every approved target worktree (agents, editors/autosave, builds/watchers, and background processes) are stopped and will remain stopped through completion of worktree removal. Generic cleanup approval does not imply this quiescence assertion. If it is absent or uncertain, pause that removal and preserve its branch; no enforced concurrency or locking mechanism is introduced.

Pause for the user's answer. Invocation itself is not confirmation. If there are no eligible branches, report that outcome; ask separately before a prune-only operation. Bind approval to the listed branch tips, worktree paths, PRs, ignored-path snapshots, effective status-configuration results, and remote—not future discoveries—and record the explicit quiescence assertion for approved worktree removals.

## Clean up approved candidates

1. After explicit confirmation and before any approved worktree or branch removal, recheck repository/remote identity and inspect configured fetch refspecs and effective prune settings. If they could prune local branches, tags, or other non-tracking refs, pause for reconciliation rather than using them. Run `git fetch --prune <verified-remote>` once per invocation to prune only stale remote-tracking branch refs using standard branch refspecs. Verify and record the pruning outcome before proceeding; a failed or uncertain outcome requires reconciliation. Do not delete remote branches or tags, run `git prune`, or expire reflogs.
2. Immediately before each worktree or branch removal, recheck repository/remote identity, PR merge/head state, local and remote tips, worktree paths/associations, locks, and exclusions. Changed evidence invalidates approval for that candidate; skip it and report the reason. If a matching remote branch was deleted after preview, re-establish the PR head evidence before proceeding. Content changes alone do not invalidate otherwise unchanged approval: there is no full-cleanliness, ignored-content, or submodule eligibility recheck.
   - Immediately before each worktree removal, re-establish the applicable effective status configuration using Inspect's context-equivalence prerequisite, and reconfirm with the operator that the explicit stopped-writers condition is still established through completion of removal. A changed configuration result requires reconciliation and fresh confirmation, even if still safe. Unsafe/unknown configuration or absent, uncertain, or lost quiescence pauses that removal and preserves its branch. Resumption requires reconciliation and renewed explicit quiescence confirmation; do not mutate configuration or inject overrides to proceed.
3. Remove each approved worktree with plain `git worktree remove <absolute-path>` from a retained worktree outside the removal target, in the context whose internal status configuration was established. This is the sole worktree deletion mechanism: no `--force`, unlocking, direct filesystem deletion by the skill, manual fallback, or automatic stashing. Git's own recursive deletion is permitted, subject to its non-atomic boundary disclosed above. Treat a Git refusal as fresh evidence: preserve the branch, report the blocker, and do not retry removal. This includes refusals involving untracked/modified content or populated submodules, even clean populated submodules; dropping the skill-side gate does not promise Git will remove them.
4. After all associated worktrees have been successfully removed, verify no worktree still uses the branch and recheck the exact approved ref/evidence as in step 2, then delete that local branch with `git branch -d <branch>`. If Git refuses solely because squash/rebase merging prevents ancestry-based deletion, recheck the confirmed PR/head evidence and use `git branch -D <branch>` only for that approved, unchanged ref. Other failures require investigation, not a blanket force retry. Verify branch absence and removed worktree registration/path. `git worktree remove` handles normal registration cleanup; stale/missing worktree records need a separate explicit decision.

## Finish and resume

Report removed worktrees/branches, preserved candidates with reasons, pruned remote-tracking refs, failed operations, and remaining input. Verify actual state; partial cleanup is not full success. On interruption, re-inventory before continuing, recognize actual completed effects (pruning and removals), and obtain fresh confirmation for changed or newly discovered candidates. Do not repeat completed pruning or removals within the resumed invocation; uncertain effects require reconciliation, not an assumption of success. Preserve original approved identities when continuing unchanged partial work, without retrying a refused worktree removal. Before resuming any remaining worktree removal, reconcile its current evidence/configuration and obtain renewed explicit stopped-writers confirmation, then perform the immediate prerequisites/recheck above. Preserve the branch whenever removal is paused or refused.
