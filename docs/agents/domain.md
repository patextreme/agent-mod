# Domain docs

## Before exploring

This repository uses a single-context layout:

- Read root `GLOSSARY.md`.
- Read decisions in `docs/adr/` relevant to the work.

If either is absent, proceed silently. Domain documents are created
lazily when terminology or decisions are resolved.

## Vocabulary

Use glossary terms when naming domain concepts in issues, proposals,
code, and tests. Respect explicitly avoided synonyms.

If a needed concept is missing, reconsider the terminology or note
the gap for domain modeling.

## ADR conflicts

Explicitly surface any proposed contradiction of an existing ADR,
including which decision would need reconsideration and why.
